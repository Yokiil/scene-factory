# 技术交底草稿：任务约束与物理依赖图驱动的仿真环境增量构建及验证

2026-11-04 补充：本文件保留原始研究设计；新增 MuJoCo 对象片段增量、受限模型参数更新、
新接触包络查询及四组实测见 [增量编译交付](../sandbox/INCREMENTAL_COMPILER_20261104.md)。
新增结果仍不证明一般机器人环境的局部动力学验收充分性或专利新颖性。

日期：2026-10-28。本文是用于进一步研究和专利沟通的技术交底草稿，不是新颖性意见、
专利申请文件或已经完成全部实验的技术成果声明。需结合现有技术检索和对照实验继续修改。

## 技术问题

机器人训练环境会反复改变初始位姿、材质、质量、摩擦、零件尺寸和任务条件。
全量导出与引擎加载可能重复计算未变部分；普通文件缓存不能充分表达物理参数与惯量、
装配几何、接触和验证证据之间的依赖。另一方面，仅沿旧接触关系失效也不可靠：
位姿、质量、摩擦或控制器变化都可能导致新接触，旧图没有观察到的关系仍可能影响任务。

## 拟研究的机制

1. 在环境编译时，记录资产几何、实例变换、实例物理参数、支撑/关节、装配接口、任务阈值、
   控制器及编译产物之间的依赖图。输入和产物分别使用内容摘要标识。
2. 将一个环境变体与已编译环境比较，识别发生变化的节点，计算传递依赖闭包。
   例如仅质量变化时，几何内容可复用，但质量/惯量和相关动力学证据必须失效。
3. 对可能改变运动或接触的输入，重新查询保守运动包络内的候选交互，纳入新增接触及支撑。
   无法证明包络完整、或发生拓扑/工作空间变化时，保留未失效编译内容，但全量重跑动力学
   和任务验收，不能因局部缓存命中而沿用旧成功结论。
4. 在 episode 边界应用重新构建后的环境，记录环境摘要、工具/引擎/求解器版本、实例最终
   参数，以及本次重建/复用节点、失效原因、耗时和验证范围。
5. 以同一任务约束确定固定的物理精度区域；只有证明不影响工作区接触的背景，才允许使用
   简化碰撞几何。初版不在接触过程中在线切换碰撞精度。

## 当前代码已落地的部分

- `physics_dependencies.py`：依赖图、传递闭包、场景差异计划和保守证据失效；
- `environment_package.py`：MuJoCo 输入冻结、运行锁、内容摘要、编译缓存和未变内容块复用；
- `constrained_randomization.py`：独立随机数流、实例参数覆盖、质量/惯量相关缩放和接口间隙拒绝；
- `assembly.py`：两件式接口坐标系和测量轨迹判据，可用于后续物理任务对照；
- MuJoCo 后端：兼容模型重置复用及状态恢复，具体实测见相应运行报告。

当前改变 MJCF 内容时仍全量生成该 MJCF；依赖图没有驱动引擎内的局部对象替换。
本版没有计算并证明完整的保守运动包络，因此任何变化都要求完整动力学/任务重验。
这些已实现的工程能力是验证候选机制的基础，不能单独作为新颖性或创造性已成立的依据。

## 必须补充的四组对照

以下四组对照尚未完整执行：

| 组别 | 构建策略 | 需要控制的一致条件 |
| --- | --- | --- |
| A | 每次全量导出、编译、加载和验证 | 同场景、硬件、引擎、求解器、控制器与误差门槛 |
| B | 普通文件/内容哈希缓存 | 与 A 相同；记录缓存命中及未命中输入 |
| C | 物理依赖图驱动局部编译，并按充分性规则验证 | 不得降低任务判据或漏掉新增接触 |
| D | C 加上构建时固定的任务精度区域 | 单独报告精度变化与任务成功率，不只报告加速 |

变体至少覆盖质量/惯量、摩擦、初始位姿、孔径、碰撞网格、控制器参数和拓扑变化。
记录 P50/P95 编译/加载/验证耗时、节点重建比例、峰值资源、任务成功/失败率、
与全量构建的状态/接触/任务结果差异，以及需要全量回退的比例和原因。

需要特别加入“旧关系图中没有接触，变更后产生新接触”的负例，以及惯量未随尺度正确
变化、孔径/插销不兼容、缓存沿用旧物理证据等故障注入。若收益来自精度降低或跳过验证，
应作为独立变量报告，不应计作相同质量下的构建效率收益。

## 现有技术检索和边界

后续检索应覆盖增量编译/构建系统、OpenUSD 分层与实例化、仿真资产管线、物理域随机化、
碰撞 broad-phase/连续碰撞检测、任务相关保真度分配、GPU 仿真批处理、机器人装配验证，
以及近邻技术中对缓存证据与依赖闭包的处理。不能仅因使用了“物理依赖图”命名就认定
与既有 scene graph、数据流图、依赖追踪或增量求解方法存在可专利差异。

可能具有独立技术价值的研究点是：任务约束、参数推导和新增接触闭包如何共同决定失效范围，
哪些充分条件允许局部验证，以及这些条件的检查成本与加速收益。需在检索和实验之后确定
具体权利要求范围；目前不建议把 CLI、容器、普通缓存或自动化本身作为核心创新点。
