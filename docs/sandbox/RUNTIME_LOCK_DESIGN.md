基准报告中的输入/代码摘要有助于定位运行条件，但不能替代完整依赖闭包。

## 与已有格式的关系

保留 `.scene.zip` v1 的语义；新环境清单使用独立 schema
`scene_factory.runtime_lock.v1`，在环境包中以 `runtime/lock.json` 保存。
场景包保持静态资产交付职责，运行锁描述该包在某种后端上的具体执行配置。
一个场景包可对应多个后端锁，不能共用动力学验收证据。

拟定的顶层字段：

| 字段 | 内容及校验要求 |
| --- | --- |
| `schema_version` | 固定版本，未知版本拒绝；升级使用显式迁移器 |
| `scene` | 布局/任务内容摘要、原场景包摘要、坐标/单位、拓扑摘要 |
| `dependencies` | 每个依赖的角色、内容 SHA-256、大小、相对路径或解析源、许可来源 |
| `instances` | 最终生效的位姿、质量/质心/惯量、摩擦等及来源；缺失字段拒绝宣称完全锁定 |
| `engine` | 后端、版本、插件、物理 dt、求解器、碰撞设置、单位 |
| `controller` | 实现及配置摘要、动作模式、控制周期、限位和夹爪语义 |
| `task` | 判据版本、阈值、超时、成功/失败规则摘要 |
| `randomization` | 算法版本、独立流标识、seed、范围/相关性约束、实际采样值 |
| `observations` | 传感器版本、模态、内外参、采样周期、噪声配置和时间对齐规则 |
| `runtime` | 镜像内容摘要、Python/数值库版本、导出器代码摘要、设备兼容条件 |
| `evidence` | 输入锁摘要、验证器版本、适用范围、报告/轨迹哈希、passed/failed/not_verified |

运行时 GPU、宿主驱动和资源使用值写入会话运行证据，同时检查锁文件声明的兼容条件。
不把运行时硬件描述伪装成可装入容器的依赖，不承诺跨硬件或跨引擎逐位一致。

## 摘要和循环依赖

规范化采用 UTF-8、对象键排序、紧凑 JSON 和有限数值；数字表示必须随 schema 冻结。
定义 `environment_sha256` 为不含 evidence、该摘要自身及下载地址的可执行配置摘要。
依赖内容变化必须改变摘要；仅改变镜像位置不改变其内容身份。
证据引用环境摘要，证据报告自身另行哈希，避免环境清单与证据互相哈希形成循环。
episode 扰动由环境模板锁加具体采样清单导出新的 episode 摘要。

## 构建、加载和失效

1. 构建时解析场景使用的依赖闭包，包括 USD 引用/子层/纹理、机器人资源、碰撞几何、
   导出器读取的网格文件与运行插件。根 USD 或 registry 的哈希不足以代替闭包。
2. 依赖解析模式按哈希取缓存；离线完整包模式包含全部必需资源。缺文件、许可/获取权限
   不满足、哈希不匹配或无法解析的动态依赖都使构建失败，不能生成标为完整的锁。
3. 加载前验证依赖、版本、能力与参数，不支持的动作、传感器或求解器设置明确拒绝。
   建立受锁保护的输入副本，避免源码文件在 reset 间变化。
4. 编译产物缓存与运行证据缓存分别索引。质量/摩擦等变化可以复用未受影响的视觉资源，
   但动力学/任务证据必须失效；控制器、判据、传感器或求解器变更也使相关证据失效。
5. 当前阶段仅支持重建到 episode 初始条件。未来状态快照另有 schema，声明后端兼容范围、
   不能序列化的求解器状态和测量偏差，不把 USD 或单帧 JSON 作为精确 checkpoint。

实现验收应覆盖：内容变化导致失效、资源路径变化但内容一致、缺依赖、版本不兼容、
旧 v1 场景包可读、证据不能跨输入摘要复用，以及离线解析过程无隐式联网依赖。
